# 订单结算体验设计

## 目标

将当前 FitMe 的商品推荐、购物车和 Java 订单服务连接为完整的用户闭环：已登录用户可以从推荐或商品详情加入购物车，确认商品金额后创建订单，在移动端查看订单并取消尚未处理的订单。

本次不修改 Python RAG 的检索、Agent 或模型调用流程；商品目录仍由 Python 服务提供，用户、购物车和订单继续由 Java 服务负责。

## 范围

### 购物车结算

- 购物车抽屉展示商品数量、金额合计和提交订单入口。
- 提交前要求用户已登录且购物车非空。
- 前端为每次提交生成并传递 `Idempotency-Key`，避免重复点击创建多笔订单。
- 创建成功后刷新购物车和订单数据，关闭购物车并进入订单页。
- 创建失败时不修改本地购物车，展示服务返回的错误信息，并允许再次提交。

### 订单页面

- 新增移动端订单列表路由，展示订单编号、状态、商品快照、金额与创建时间。
- 订单列表为空时提供清晰的空状态和返回商品发现页的入口。
- 对可取消的订单提供取消操作；取消成功后刷新列表和详情状态。
- 个人页增加订单入口，未登录用户沿用现有登录引导。

### 前后端边界

- 复用 Java 现有接口：`POST /api/orders`、`GET /api/orders`、`GET /api/orders/{orderId}` 与 `POST /api/orders/{orderId}/cancel`。
- 前端补充订单数据类型、请求封装和状态刷新逻辑。
- 不新增 Python API，不迁移商品数据，不修改 Java 订单领域规则或数据库结构。

## 用户流程

1. 用户在 Agent 推荐、发现页或商品详情页将商品加入购物车。
2. 用户打开购物车，确认商品和合计金额后提交订单。
3. 前端携带 JWT 和幂等键调用 Java 下单接口。
4. 下单成功后，用户进入订单页查看订单及商品快照。
5. 用户可取消仍允许取消的订单；服务端返回最新状态后，页面立即刷新。

## 失败处理

- 未登录：跳转现有登录流程，不发起订单请求。
- 购物车为空：禁用提交入口。
- 网络或服务错误：保留购物车内容，展示可重试提示。
- 重复提交：由同一幂等键保证服务端只创建一次订单；按钮在请求期间禁用。
- 取消失败：保留当前订单显示并给出错误信息。

## 测试与验收

- 前端请求层测试：创建订单携带认证和幂等键；订单列表、取消订单的成功与失败响应。
- 组件交互测试：空购物车不可结算，提交中不可重复点击，成功后刷新状态。
- 现有 Java 订单集成测试保持通过。
- 手工验收：注册或登录 -> 加入商品 -> 提交订单 -> 查看订单 -> 取消订单。

## 非目标

- 真实支付、库存扣减、物流、优惠券。
- 修改 Python RAG 主流程或重新训练模型。
- 改造现有订单状态机和数据库表。
