# 天池淘宝服装搭配数据集导入设计

## 目标

将本项目的演示商品目录从 H&M 样本替换为天池公开的“淘宝服装搭配数据集（Fashion Collection Dataset）”。首次构建固定导入 5,000 件带有可用图片的商品，同时保持现有 Java 用户、购物车、订单接口以及 Python RAG 查询接口不变。

## 范围与约束

- 只替换商品目录数据和数据导入工具；不修改 Python RAG 的检索、Agent 或模型调用逻辑。
- 不修改 Java 领域模型、购物车、订单或前端 API 合约。
- 天池原始压缩包、解压后的图片、SQLite 库和向量索引均为本地或服务器运行数据，必须继续被 Git 忽略。
- 商品图片不能写入 Git；部署时须与 SQLite 库一起上传至虚拟机。
- 数据集的许可、下载资格与署名要求以天池下载页面的说明为准。

## 设计选择

采用“新增天池导入器，复用既有商品契约”的方案，而不直接改写或删除 H&M 导入脚本。

现有服务已经将商品图片路径转换为 `/media/<相对路径>`，并通过 Java 网关代理给 Python 静态资源服务。因此导入器只要生成与当前目录契约一致的商品 CSV、图片目录和 SQLite 库，调用方无需变更。

## 输入与输出

### 输入

用户从天池下载的原始数据包放在 `backend/data/raw/`。导入器只处理带有以下信息的记录：唯一商品标识、商品标题或描述、至少一个本地图片文件；类别、颜色、价格和行为热度可选。

导入器在运行开始时打印已发现的数据文件、字段名和图片文件数量。运行命令必须显式给出商品 ID、名称与图片路径的字段名；CSV 表头缺少其中任一字段时直接失败。该规则不依赖猜测首行是否像表头，能够适配天池不同版本的字段命名。若无法确定商品元数据文件或找不到任何图片，会直接失败，不会覆盖当前商品库。

### 输出

导入完成后生成以下现有运行时文件：

- `backend/data/sample/articles_sample.csv`：规范化后的 5,000 条商品记录。
- `backend/data/sample/images/`：每条商品记录对应的一张图片，`image_path` 必须相对该目录且不可越界。
- `backend/data/sqlite/app.db`：由现有 `build_sqlite.py` 生成的商品库。
- `backend/data/vector_store/text/`：由现有 `build_text_index.py` 生成的文本检索索引。
- `backend/data/sample/catalog_manifest.json`：记录来源名称、导入时间、随机种子、商品数、图片数和各输出文件 SHA-256，用于复现与部署校验。

输出先写入同级临时目录，所有校验通过后再原子替换正式目录，避免部署中断时留下半成品。

## 字段映射

导入器统一输出当前 `PRODUCT_FIELDS` 所要求的字段。天池字段名称由导入时实际文件的列名确定，但语义映射固定：

| 现有字段 | 天池数据语义 | 缺失时的值 |
| --- | --- | --- |
| `article_id` | 商品唯一 ID | 不允许缺失 |
| `product_code` | 商品或款式 ID | 同 `article_id` |
| `prod_name` | 商品标题 | 不允许缺失 |
| `product_type_name` | 细分类 | `未分类` |
| `product_group_name` | 大类 | `服装` |
| `colour_group_name` | 颜色或色系 | `未知` |
| `detail_desc` | 商品描述或标题 | 使用 `prod_name` |
| `image_path` | 选定图片的相对路径 | 不允许缺失 |
| `price` | 数据集提供的价格 | `NULL` |
| `popularity_score` | 行为数据聚合热度 | `0` |

其余现有文本字段写为空字符串。文本索引继续从这些规范化字段构造 `text_profile`，因而中文商品标题、分类和描述可以直接被现有检索管线使用。

## 抽样与质量规则

- 固定随机种子 `42`，同一原始数据包重复导入得到同一组商品。
- 候选商品必须具备非空 ID、非空标题和可读取的 JPEG、PNG 或 WebP 图片。
- 按大类优先均衡抽样；若原始数据缺少大类，则使用稳定哈希抽样。
- 每个商品只保留一张主图；重复 ID、重复图片、损坏或零字节图片会被跳过并计数。
- 最终必须恰好得到 5,000 条商品、5,000 张非空图片，且 CSV 中全部图片路径均能解析到图片目录内的真实文件。
- 任一数量或路径校验失败时，导入命令非零退出，保留原有商品数据不变。

## 部署方式

1. 在开发机导入数据、构建 SQLite 库和文本索引。
2. 将 `backend/data/sample/images/`、`backend/data/sample/articles_sample.csv`、`backend/data/sample/catalog_manifest.json`、`backend/data/sqlite/app.db` 与 `backend/data/vector_store/text/` 一并上传至虚拟机对应目录。
3. 重建并重启 `backend` 服务；Java 和 frontend 服务无需因数据更新而重建。
4. 在虚拟机验证 `/api/products` 返回 5,000 条目录规模，并随机请求一个 `/media/...` 图片返回 `200`。

## 测试

- 为天池规范化逻辑准备微型夹具，覆盖必填字段、缺失可选字段、中文文本、重复 ID、无图片和损坏图片。
- 验证固定种子下的抽样结果稳定。
- 验证导入失败不替换已有输出目录。
- 使用生成的小样本运行现有 SQLite 构建与文本索引构建，验证商品数和图片路径一致。

## 非目标

- 不导入或暴露任何可识别个人身份的购买行为明细。
- 不在本次变更中训练新模型、改动推荐算法或迁移商品领域模型到 Java。
- 不将海量原始数据、图片或生成索引提交到代码仓库。
